# TravonetWG

Клиентская реализация протокола WireGuard на базе wireguard-go с встроенным механизмом обхода глубокого анализа пакетов (DPI / ТСПУ) на уровнях L3 и L4. Работает с любыми стандартными немодифицированными серверами WireGuard (включая коммерческие VPN-провайдеры и собственные серверы на Linux).

---

## Архитектура и режимы работы

TravonetWG поддерживает два основных режима функционирования:

### 1. Режим TUN (системный сетевой интерфейс)
В этом режиме программа создает системный сетевой интерфейс `tun` и маршрутизирует трафик операционной системы через WireGuard-туннель.
- Требует прав суперпользователя (`root` или capability `CAP_NET_ADMIN` и `CAP_NET_RAW`).
- Поддерживает полный спектр L3-десинхронизации: отправку фейковых пакетов и настоящую фрагментацию пакета рукопожатия (IP fragmentation) на уровне сырых сокетов (`raw sockets`) с флагами `IP_HDRINCL` и `IP_NODEFRAG`.

### 2. Режим Userspace SOCKS5 Inbound (без root)
В этом режиме программа не создает виртуальный сетевой интерфейс в операционной системе, а запускает встроенный локальный SOCKS5-прокси.
- Работает полностью без прав суперпользователя (zero-root / unprivileged).
- Сетевой стек TCP/IP реализован в пространстве пользователя с помощью встроенного gVisor netstack.
- Обход DPI выполняется на уровне непривилегированного UDP-сокета через динамическое управление TTL (`setsockopt(IP_TTL)`) перед отправкой пакетов рукопожатия (отправка `junk` и фейковых пакетов рукопожатия с коротким временем жизни).

## Механизм обхода DPI (Десинхронизация)

Стандартное рукопожатие WireGuard (Handshake Initiation) представляет собой характерный 148-байтный UDP-пакет с идентификатором типа `0x01`. Системы глубокого анализа пакетов (DPI / ТСПУ) анализируют сигнатуру и длину первого пакета сессии и сбрасывают или глушат соединение.

TravonetWG представляет собой **гибкий модульный движок-конструктор десинхронизации**: поведение при отправке рукопожатия не зашито намертво, а описывается языком DSL (Domain Specific Language). По сути протокол бессмертен, потому что менять стратегии и размеры фрагментов можно почти бесконечно.

> [!IMPORTANT]
> **Стратегии обхода должны составляться и подбираться пользователями самостоятельно.**
> Разные интернет-провайдеры, мобильные операторы и магистральные узлы ТСПУ используют различные эвристики и версии фильтров. Одной универсальной стратегии на все случаи не существует — пользователи создают свои собственные цепочки под условия конкретной сети.

### Встроенная стандартная стратегия (Fallback)

Если пользователь **не указал** собственную стратегию (ни в файле конфигурации, ни через флаги CLI), программа автоматически задействует базовую проверенную 5-шаговую стратегию десинхронизации с двойным фейком:
```text
fake(148) -> frag(8) -> frag(72) -> fake(148) -> frag(76)
```

Принцип работы стандартной стратегии:
```
[Клиент] --- (1) Fake UDP #1 (148 байт, TTL=11, 0x01) ---------> [DPI / ТСПУ] (травит состояние) ---X (умирает в пути)
         --- (2) Фрагмент #1 (offset=0, len=8, MF=1, TTL=64) --> [DPI / ТСПУ] ---> [Сервер WireGuard]
         --- (3) Фрагмент #2 (offset=8, len=72, MF=1, TTL=64) -> [DPI / ТСПУ] ---> [Сервер WireGuard]
         --- (4) Fake UDP #2 (148 байт, TTL=11, 0x01) ---------> [DPI / ТСПУ] (сбивает сборщик) ---X (умирает в пути)
         --- (5) Фрагмент #3 (offset=80, len=76, MF=0, TTL=64) -> [DPI / ТСПУ] ---> [Сервер WireGuard]
```

1. **Fake UDP #1 (`fake(148)`):** Отправка фейкового пакета рукопожатия с коротким значением TTL. Пакет достигает узлов ТСПУ (обычно 8-11 хопов на магистралях), регистрируется в таблицах DPI как сессия и отбрасывается маршрутизаторами в пути, не доходя до реального сервера.
2. **Фрагмент #1 (`frag(8)`):** Первый IP-фрагмент содержит только 8 байт UDP-заголовка (порты) без тела WireGuard (`MF=1`).
3. **Фрагмент #2 (`frag(72)`):** Второй IP-фрагмент содержит 72 байта полезной нагрузки (смещение 8..80, `MF=1`).
4. **Fake UDP #2 (`fake(148)`):** Промежуточный фейковый пакет с коротким TTL, сбивающий сборщик пакетов на ТСПУ при попытке реассемблирования сессии.
5. **Фрагмент #3 (`frag(76)`):** Завершающий IP-фрагмент, содержащий оставшиеся 76 байт полезной нагрузки (смещение 80..156, `MF=0`). Сервер WireGuard собирает все три фрагмента в полноценный 156-байтный пакет и успешно завершает рукопожатие.

## Автоматическое определение TTL (Auto-TTL)

Для того чтобы фейковый пакет гарантированно дошел до оборудования ТСПУ на магистральных каналах провайдера, но не дошел до зарубежного сервера WireGuard, его значение TTL должно быть рассчитано корректно.

В TravonetWG встроен механизм зондирования маршрута (`Auto-TTL`):
- Клиент в фоновом режиме перед запуском отправляет короткую серию зондирующих пакетов и определяет общее число хопов до конечного узла.
- Оптимальный TTL для фейка вычисляется по формуле `totalHops - 4`, с ограничением диапазоном 8-11 хопов (зона действия ТСПУ).
- При значении `FakeTTL = auto` или передаче CLI-флага `--fake-ttl auto` подбор осуществляется автоматически.

## Язык DSL: написание собственных стратегий

Пользовательские стратегии формируются как последовательность шагов, соединенных оператором `->`:

| Команда | Описание | Пример |
| :--- | :--- | :--- |
| `junk(size, [badsum])` | Отправка случайного UDP-пакета заданного размера | `junk(64)`, `junk(size=128, badsum=true)` |
| `fake_udp(size, [ttl])` | Полный UDP-пакет с фейковым заголовком рукопожатия | `fake_udp(148)`, `fake_udp(size=148, ttl=10)` |
| `frag(offset, len, [mf, ttl])` | Настоящий фрагмент пакета рукопожатия | `frag(8)`, `frag(offset=0, len=8, mf=true)` |
| `fake_frag(offset, len, [mf, ttl])` | Инъецируемый фейковый IP-фрагмент | `fake_frag(offset=88, len=32, mf=0, ttl=10)` |
| `sleep(duration)` | Пауза между отправкой пакетов | `sleep(10ms)` |

### Примеры пользовательских стратегий

- **Чистая фрагментация транспортного заголовка (без фейков):**
  `frag(8) -> frag(148)`
- **Pre-Junk увеличенного размера + чистая фрагментация:**
  `junk(128) -> frag(8) -> frag(148)`
- **Инъекция фейкового UDP-пакета между фрагментами:**
  `frag(8) -> fake_udp(148, ttl=9) -> frag(148)`
- **Фрагментация с тайминговыми задержками:**
  `junk(64) -> sleep(10ms) -> fake_udp(148) -> sleep(5ms) -> frag(8) -> frag(148)`
- **Инъекция фальшивого фрагмента:**
  `junk(64) -> fake_frag(offset=0, len=8, mf=true, ttl=8) -> frag(8) -> frag(148)`
- **Для непривилегированного Userspace (без root):**
  `junk(64) -> fake_udp(148)`

Подробный каталог стратегий и детальное описание их поведения собраны в файле [strategies.txt](strategies.txt).

## Передача стратегий в программу

Пользовательскую стратегию можно передать двумя способами.

### Способ 1: Внутри конфигурационного файла .conf
Директива `Strategy` указывается в секции `[Interface]`:

```ini
[Interface]
PrivateKey = aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa
Address = 172.16.0.2/32
DNS = 1.1.1.1
MTU = 1280

# Пользовательская стратегия десинхронизации:
Strategy = fake(148) -> frag(8) -> frag(72) -> fake(148) -> frag(76)
FakeTTL = auto
PreJunk = 64

[Peer]
PublicKey = bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb
Endpoint = 162.159.192.1:2408
AllowedIPs = 0.0.0.0/0
PersistentKeepalive = 25
```

Запуск:
```bash
sudo ./travonet-wg -f -c my-config.conf wg0
```

### Способ 2: Через аргументы командной строки
Флаг `-s / --strategy` имеет наивысший приоритет и переопределяет как значение из `.conf`, так и стандартную стратегию:

```bash
# Передача пользовательской стратегии через CLI:
sudo ./travonet-wg -f -c clean.conf -s "junk(32) -> fake_udp(148, ttl=8) -> frag(8) -> frag(148)" wg0

# Установка конкретного TTL фейка:
sudo ./travonet-wg -f -c clean.conf --fake-ttl 10 wg0

# Запуск стандартного wireguard-go без обхода DPI:
sudo ./travonet-wg -f -c clean.conf --no-evasion wg0

# Если флаги не переданы и в конфиге нет Strategy, используется встроенный дефолт:
sudo ./travonet-wg -f -c clean.conf wg0
```

## Примеры запуска

### 1. Запуск локального SOCKS5-прокси (без прав root)
Запуск прокси-сервера в пространстве пользователя (адрес и порт опциональны, по умолчанию `127.0.0.1:1080`):

```bash
# Запуск на стандартном адресе 127.0.0.1:1080 (без указания адреса):
./travonet-wg -c client.conf --socks

# С указанием только порта:
./travonet-wg -c client.conf --socks 1088

# С указанием конкретного интерфейса и порта:
./travonet-wg -c client.conf --socks 0.0.0.0:1088
```

Проверка соединения через curl:
```bash
curl -x socks5h://127.0.0.1:1080 https://ifconfig.me
```

### 2. Запуск системного VPN через скрипт run_tunnel.sh (с правами root)
Скрипт `run_tunnel.sh` автоматически настраивает системную маршрутизацию и DNS для направления всего интернет-трафика через туннель:

```bash
# Стандартный запуск с автоматическим подбором TTL:
sudo ./run_tunnel.sh client.conf

# Запуск с указанием конкретного TTL для фейковых пакетов:
sudo ./run_tunnel.sh client.conf --fake-ttl 10
```

Проверка маршрутизации:
```bash
curl https://ifconfig.me
```

### 3. Прямой запуск с созданием интерфейса tun (с правами root)
```bash
sudo ./travonet-wg -f -c client.conf wg0
```

## Версия для Windows

TravonetWG полностью адаптирован для работы в операционных системах семейства Windows (x86_64 и x86).

### 1. Режим Userspace SOCKS5 (без прав администратора и без драйверов)
В этом режиме программа не требует прав администратора и сторонних драйверов:
- Сетевой стек TCP/IP эмулируется в оперативной памяти процесса через gVisor netstack.
- Десинхронизация DPI (отправка `pre-junk` UDP и фейковых пакетов инициализации с пониженным TTL) выполняется через стандартные системные вызовы Winsock `setsockopt(IPPROTO_IP, IP_TTL)`.

Запуск:
```cmd
travonet-wg.exe -c client.conf --socks
```
или с указанием конкретного порта:
```cmd
travonet-wg.exe -c client.conf --socks 127.0.0.1:1080
```

### 2. Режим системного адаптера TUN (Wintun)
Для создания полноценного сетевого адаптера в Windows и маршрутизации всего трафика системы:
- Требуется запуск командной строки или PowerShell от имени Администратора.
- В каталоге с программой или в системном каталоге `C:\Windows\System32` должна находиться библиотека `wintun.dll` (официальный драйвер Wintun от разработчиков WireGuard).
- Программа автоматически настраивает IP-адрес интерфейса, DNS и маршруты Windows через утилиты `netsh` и `route`.

Запуск от имени Администратора:
```cmd
travonet-wg.exe -c client.conf wg0
```

### Сборка исполняемых файлов для Windows
Кросс-компиляция из Linux выполняется с помощью скрипта `build-windows.sh`:
```bash
./build-windows.sh
```
Готовые бинарные файлы сохраняются в директории `build/windows/`:
- `travonet-wg.exe` (x86_64)
- `travonet-wg-x86.exe` (x86, 32-bit)

## Версия для Android (Нативная библиотека .so)

TravonetWG предоставляет нативную разделяемую библиотеку (`.so`) с CGO и JNI для интеграции в Android-приложения без необходимости прав суперпользователя (root).

Подробное техническое руководство по интеграции для разработчиков VPN-клиентов см. в файле [Android_guide.md](Android_guide.md).

### Особенности работы на платформе Android

1. **Режим VpnService (системный VPN):**
   - Передача дескриптора TUN через `CreateUnmonitoredTUNFromFD(tunFd)`.
   - Защита сокета WireGuard от маршрутизации в самого себя: функции `wgGetSocketV4(handle)` и `wgGetSocketV6(handle)` возвращают файловый дескриптор открытого UDP-сокета, который приложение передает в метод `VpnService.protect(socketFd)`.

2. **Обход DPI без root:**
   - Ввиду отсутствия `CAP_NET_RAW` на стандартных устройствах Android, `EvasionBind` автоматически использует непривилегированный движок десинхронизации в пространстве пользователя.
   - Десинхронизация осуществляется отправкой `pre-junk` пакетов и модификацией `IP_TTL` через стандартный вызов `setsockopt(IP_TTL)` перед отправкой фейковых пакетов инициализации.

3. **Режим встроенного SOCKS5 (Zero-Permission):**
   - Функции `wgStartSocks5(listenAddr, settings)` и `wgStopSocks5(handle)` запускают локальный прокси внутри приложения без необходимости получения системного разрешения `VpnService`.

4. **JNI-совместимость:**
   - Предоставлены JNI-символы для пакетов `com.wireguard.android.backend.GoBackend`, `org.amnezia.vpn.protocol.amneziawg.GoBackend` и `org.travonet.backend.GoBackend`.

### Сборка под Android

Скрипт `build-android.sh` автоматически компилирует нативные библиотеки для четырех основных архитектур:
- `arm64-v8a` (64-битные процессоры ARM)
- `armeabi-v7a` (32-битные процессоры ARM)
- `x86_64` (64-битные эмуляторы и планшеты x86)
- `x86` (32-битные эмуляторы x86)

Запуск сборки:
```bash
./build-android.sh
```

Готовые библиотеки размещаются в директории `build/android/jniLibs/<ABI>/`:
- `libtravonet-wg.so`
- `libwg-go.so`

## Лирическое отступление и благодарности: AmneziaWG

Хочу выразить благодарность команде проекта **Amnezia** (AmneziaWG). Их наработки и идея отправки мусорных пакетов (junk) перед хэндшейком стали для меня первоначальным вдохновением.

В то же время схема обфускации в AWG устроена достаточно просто — через статическую замену заголовков (`magic headers`) и базовый шум. Современные системы ТСПУ быстро обучаются на таких паттернах, из-за чего подобную защиту со временем становится несложно заблокировать.

Именно поэтому я решил создать более сложное и гибкое решение. Вместо статической маскировки TravonetWG реализует активную десинхронизацию DPI на уровнях L3/L4 (отравление таблиц сессий фейками с коротким TTL, нарезка IP-фрагментов и произвольные конвейеры DSL). Это позволяет работать с любым ванильным сервером WireGuard и делает обход адаптивным: менять стратегии и размеры фрагментов можно бесконечно.

При этом подчеркну: **код AmneziaWG в проекте не использовался и не копировался**. Вся система десинхронизации и userspace-стек написаны с нуля на базе `wireguard-go`. В нативной Android-библиотеке сохранена лишь совместимость с их JNI-интерфейсом (`org.amnezia.vpn.protocol.amneziawg.GoBackend`) для удобного подключения к существующим мобильным клиентам.
